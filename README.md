# 天启 · 学生方案管理后台

家长为孩子建档提交，总管审核后按「问题 × 孩子周岁」自动匹配方案答复，方案延时给出，家长反馈再逐级回复。

## 技术栈

前端是 Vite + React 19 + TypeScript 单页应用，UI 基于 [Launch UI](https://github.com/launch-ui/launch-ui)（Tailwind v4 + shadcn/ui new-york），后端直连 Zion BaaS 的 Runtime GraphQL，没有自建服务端。

## 角色与流程

| 角色 | 职责 |
| --- | --- |
| 家长 | 填写四份表单建档、提交审核、查看方案、提交反馈 |
| 总管 | 审核方案、设定审核等级与给出时间、指派人员、终审反馈 |
| 总监 | 审核监护专员的回复，二级审核下直接撰写回复 |
| 监护专员 | 三级审核下首先撰写回复 |
| 客户端管理者 | 开通名下家长账号、分配方案名额 |
| 超级管理员 | 账号、名额、标签题库与方案答复库维护 |

方案状态：草稿 → 待审核 → 已驳回 / 待给出 → 已给出 → 已结束。
反馈按方案审核等级决定起始环节：一级从总管起，二级从总监起，三级从监护专员起。

## 本地开发

```bash
npm install
npm run dev
```

开发环境可用 `?mock=<角色>` 预览各角色界面，例如 `/?mock=家长`。数据请求仍走真实权限。

## 构建与部署

```bash
cd web
npm run build
```

产物在 `dist`。部署到 Zeabur，构建配置见根目录 `zbpack.json`。

## 安全边界

授权全部由 Zion 的表、列、行三级权限表达，前端不承担鉴权。关键约束：

- 家长对帐户表只能改头像、姓名和已用名额，且已用名额只增不减、不得超过管理者分配的总额
- 家长只能建属于自己的草稿方案，只能把草稿或已驳回改成待审核
- 总监与监护专员只能看到指派给自己的方案及其关联数据
- 反馈状态机限定每个角色的可写状态，监护专员无法跳过上级审核直接标记为已回复
- 方案编号带唯一约束，客户端生成后冲突会自动重试
